# 全固件范围与上下文扫描（2026-11-23）

> 修正：a1330 的模块数据不是从 `0xB0` 开始。`0xB0` 是 32 字节模块头
> （名字/偏移字段），a1330 的实际 payload 从 **`0xD0`** 开始（开头是
> `20 00 FA 30 00 00 C2 0D ...` 的 MSP/reset 向量）。下面用修正后的
> `a1330_v2` 重新扫描。

## 2. 上下文常量扫描

在四个模块里搜 `0x90001046` / `0x9000104E` / `0x4007C3D0`：

| 模块 | `0x90001046` | `0x90001040`（原始命中） |
|---|---:|---:|
| a1330（修正后 `0xD0` 起） | 0 | 9（反汇编看是 `add.w`/`str` 等指令字节，不是可靠指针） |
| wma | 0 | 0 |
| tpj | 0 | 0 |
| b1330 | 1（`ldr` 字面量） | 2（`ldr` 字面量） |

结论：

- **除 b1330 外，没有任何模块直接出现 `0x90001046` 字面量。**
- a1330 修正后（`0xD0` 起）仍有 9 个 `0x90001040` 原始命中，但反汇编确认
  它们落在 `add.w`/`str` 等指令字节中间（例如 `0x285F4` 是 `add.w` 的
  立即数字节），**不是可靠指针**。
- 因此“全固件里直接找到初始化代码”这条假设目前不成立；`0x90001046`
  更可能由 **boot ROM** 或运行时计算写入，而不是某个现成模块。
